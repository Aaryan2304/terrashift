# Reconciliation of the Day-1 audit with the corrected pipeline

The Day-1 audit (`outputs/audit/data_audit.md`) and the classical baseline
(`outputs/audit/classical_baseline_pair_A.md`, `_B.md`) were produced before the
observation-validity chain and the masked registration existed. Their numbers
are historical. This note maps each of them to the corrected value and says
which one is authoritative.

Nothing here replaces a file. The old reports stay in place, because a
before/after comparison is itself evidence.

## What changed between the two pipeline versions

1. **Registration is masked.** ECC now ignores cloud, cirrus, saturated and
   defective pixels. The shift moved from (-0.118, -0.639) px to
   (-0.122, -0.639) px for Pair A, and stayed identical for Pair B.
2. **Observation validity exists.** Source NoData, `MSK_CLASSI`, `MSK_QUALIT`
   and the registration coverage now form one paired mask. Before this, "valid"
   meant only "finite reflectance".
3. **The change score is reference-scaled.** The earlier normalisation
   comparison standardised each date by its own standard deviation; that makes
   the score depend on both scene-wide distributions.
4. **The normalisation comparison now applies the registration shift.** The old
   script compared the two dates without aligning them, which inflates every
   absolute difference it measured.

## Normalisation

The raw mean absolute difference before correction dropped between the two
runs, because the corrected run aligns the dates first:

| Pair | Day-1 baseline MAE | Corrected baseline MAE |
|---|---|---|
| A | 0.02403 | 0.014841 |
| B | 0.01411 | 0.012051 |

The relative reductions are therefore not comparable across versions:

| Pair | Method | Day-1 reduction | Corrected reduction |
|---|---|---|---|
| A | global | 69.6 % | 39.6 % |
| A | histogram | 66.9 % | 36.5 % |
| B | global | 45.8 % | 32.0 % |
| B | histogram | 45.1 % | 31.5 % |

The corrected ordering also differs: Day 1 put histogram first, the corrected
stable-land comparison puts a global fit first. The positive-control experiment
on the 13 OSCD development regions then put histogram back in front on change
preservation. All three results are in the repository; the report cites the
corrected ones and states the conflict.

Source: `outputs/audit/normalization_comparison.csv` (historical) and
`outputs/audit/normalization_v2_observation_valid/normalization_comparison.csv`
(corrected).

## Classical baseline

| Quantity | Historical report | Corrected run |
|---|---|---|
| Pair A threshold (99.0 percentile) | 4.2968297 | 4.310922 |
| Pair A candidate pixels / components | 11,554 / 484 | 11,535 / 482 |
| Pair A largest component | 262 px (104,800 m²) | 262 px (104,800 m²) |
| Pair B threshold | 5.3880568 | 5.396969 |
| Pair B candidate pixels / components | 67,145 / 2,133 | 67,206 / 2,135 |
| Pair B largest component | 717 px (286,800 m²) | 719 px (287,600 m²) |

The mask shifted by less than one percent because these four products are almost
cloud-free: the validity mask removes 2,411 of 30,140,100 pixels for Pair A and
59 for Pair B. The change that does matter is the score scale: removing a
handful of saturated pixels from the reference-date standard deviation raised
every score by about 0.37 %, which moved the threshold and the component count.

Source: `outputs/audit/classical_baseline_pair_A.md` (historical) and
`outputs/baseline_v2_observation_valid/` (corrected).

## Water masks

The Day-1 plan promised `outputs/audit/water_masks.tif` as an audit output, but
no script ever wrote it. It now exists per pair as
`outputs/audit/water_masks_<PAIR>.tif` with the class encoding documented in
`docs/report.md`, generated by `scripts/make_audit_outputs.py` from the
corrected validity mask.

## What remains historical

`outputs/audit/data_audit.md`, `outputs/audit/classical_baseline_pair_A.md` and
`_B.md` are kept unchanged as the Day-1 record. They are not deleted and not
rewritten. A reader must treat their numbers as the pre-correction state.
